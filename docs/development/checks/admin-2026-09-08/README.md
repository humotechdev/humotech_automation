# Материалы проверки раздела «Администрирование», 8 сентября 2026

Снято на изолированном стенде: CRM `http://127.0.0.1:5174`, backend
`humotech-e2e-live` (рабочее дерево, база `humotech_e2e`), внешняя
доставка — stub. Настоящие сотрудники и рабочая база не затронуты.

Размеры в именах файлов — **фактические `innerWidth × innerHeight`**,
измеренные в момент снимка, а не размер окна и не разрешение панели.
Их три разные величины, и путать их нельзя: панель здесь 1920×1080
физических точек, при масштабе Windows 125 % это 1536×864 CSS-px,
рабочая область — 1536×816, а на страницу остаётся ещё меньше.

## Чего в этих материалах нет

**Настоящего полноэкранного режима.** Нажатие F11 через инструмент
уходит в страницу, а не в браузер: `innerWidth/innerHeight` не меняются,
`document.fullscreenElement` остаётся пустым. Проверка размера области
страницы полноэкранным режимом не является, и выдавать одно за другое
здесь не стали.

**Размеров 1366×768, 1536×864, 1920×1080.** Команда изменения размера
окна отвечает успехом и не меняет измерений, пока окно развёрнуто, а
высота 768 и больше на этом экране недостижима вовсе: рабочая область
816 CSS-px минус хром браузера. Один раз окно всё же оказалось
`1254×596` — этим и воспользовались, см. ниже.

## Что дал случайно доставшийся 1254×596

На этом размере обнаружилась и подтвердилась горизонтальная прокрутка
ВСЕЙ страницы на 138 px при открытой карточке: таблица учётных записей
честно скроллилась внутри своего `.scroller`, но корневой элемент всё
равно набирал лишнюю ширину и уводил вбок вместе с содержимым боковое
меню. Исправлено `html { overflow-x: clip }`; вертикальная прокрутка
сохранена. Проверено инвариантом: с заведомо широким блоком на странице
`scrollWidth` остаётся равным `clientWidth`, а `scrollLeft` — нулю.
