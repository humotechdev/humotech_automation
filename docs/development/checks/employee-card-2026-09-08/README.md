## Что было сломано

Плитки показателей были размечены классами `card`, `card__title`,
`card__value`, `card__note`, **которых в `crm.css` не существует вовсе**.
Измерено на пробной странице с тем же файлом стилей:

| Свойство | Было | Стало |
| --- | --- | --- |
| фон плитки | `rgba(0,0,0,0)` | `#fff` |
| рамка | `0px none` | `0.8px solid #e7e7e7` |
| внутренние отступы | `0px` | `18px 16px 20px` |
| скругление | `0px` | `11px` |
| значение | `14px / 400` | `32px / 700` |
| подпись | `14px / 400` | `13px / 500` |
| высота плитки | зависела от переносов текста | `130px` |

Плитка без рамки и отступов не держала форму, значение печаталось
обычным текстом, а подписи переносились, потому что у `.metric__head`
не применялось обрезание в одну строку. Кэш и `!important` тут ни при
чём: правил просто не было.

Починка — перевод плиток на существующий компонент проекта `.metric`
(тот же, что на главной и в аналитике). Ещё четыре класса на странице
тоже не существовали (`marks__row`, `roster__name`, `roster__note`,
`row`); заменены на действующие. Сверка «все классы страницы против
файла стилей» теперь чистая.
