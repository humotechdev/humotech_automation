## 4. Что подтверждено живьём, а что только кодом и тестами

**Живьём на изолированном стенде `humotech_fix`** (собран из HEAD ветки, 127.0.0.1:19443, синтетические данные):
- периметр: без входа API отвечает 401/403, бот-API снаружи — 404, `/admin/` — 403, `/.env` и `/.git` — 403;
- вход без CSRF и с чужого Origin — 403; CORS с чужого Origin — 403;
- поддельные initData и Bearer Mini App — 403/401; ограничение частоты Mini App — 429 после 30 запросов;
- заголовки CRM и API (CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy); **`Cache-Control: private, no-store`** на ответах API;
- **антивирус**: чистый файл — CLEAN, EICAR — `Eicar-Test-Signature` и отказ `infected`, остановленный clamd — 503;
- миграции на базе стенда: `schedules/0004-0005`, `attendance/0007`, `audit/0002`.

**Только через настоящий HTTP-стек Django в тестах** (APIClient и `force_authenticate`, без передачи
учётных данных; вариант 2 по решению владельца): все ролевые и межобластные сценарии H-1, M-1…M-9,
L-3…L-8, L-7, графики, F-2, F-9, M-7 (админка через Django Client).

**Сценарии, которые нужно повторить реальными HTTP-сессиями на стенде** (нужны учётные записи и вход человека):
1. H-1: HR офиса A с просмотром офиса B пытается привязать `file_id` паспорта из B (через CRM).
