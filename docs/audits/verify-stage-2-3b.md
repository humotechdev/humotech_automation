### C-01 — ПОДТВЕРЖДЕНО, CRITICAL сохраняю
- `open_session_for` берёт любую OPEN-сессию без ограничения давности (`attendance/services.py:138-142`).
- На точке BOTH направление считается так: `"EXIT" if current_session is not None else "ENTRY"` (`:266`).
- `AttendanceSession` создаётся только в `attendance/services.py:369` (grep, без demo и seed).
- `manual_event` (`attendance/hr.py:783-862`) создаёт только `AttendanceEvent(source="MANUAL")`, сессию не трогает.
- Статус INVALID не присваивается нигде: только `.exclude(status="INVALID")`.
- Админки для `AttendanceSession` нет. `AttendanceCorrectionRequest` создаётся только в `core/demo/hr/requests.py:234` и `core/demo/queues.py:311`.
- По умолчанию точка — BOTH: `direction_mode: str = "BOTH"` (`qr_codes/points.py:194`), а `require_geolocation=False` (`:197`). Значит, сценарий «Пн забыл выход → Вт утром скан закрывает 24-часовую сессию → дальше учёт перевёрнут» штатный.
- Вчерашняя открытая сессия блокирует сегодняшний выезд (`attendance/field_work.py:153-159`) — подтверждено.
- Оговорка: сотрудник может сам «выровнять» учёт двойным сканом (EXIT, затем ENTRY). Мешает пауза: для печатного кода — `TOO_SOON` 60 с (`services.py:646-659`), для сменного — новый код примерно через 30 с. Испорченная сессия при этом остаётся, а у HR исправить нечем.
- Итог: CRITICAL оправдан, потому что HR не может восстановить данные, а искажение возникает при каждой забытой отметке.

### C-04 — ПОДТВЕРЖДЕНО по коду, HIGH сохраняю
- CRM отправляет `occurred_at: \`${day}T${time}:00\`` без смещения (`hr-crm/src/components/DayCard.tsx:236-242`). `addManualEvent` пересылает строку как есть (`crm.ts:1083-1089`). Подпись в форме — «время офиса» (`DayCard.tsx:257`).
- Сервер: `serializers.DateTimeField()` (`attendance/serializers.py:173`). DRF делает наивное время aware в текущем поясе, то есть в UTC (`base.py:241-243`). View ничего не пересчитывает (`attendance/views.py:526-527`).
- Дополнительный видимый симптом, которого нет в отчёте. HR в Ташкенте в 12:00 (07:00Z) вводит вход 09:00. Сервер получает 09:00Z, а это больше чем `now + 15 мин` (`hr.py:89, 819-823`). Ответ: 400 «Ручная отметка не может быть в будущем».
  - Утренние отметки «за сегодня» массово отклоняются.
  - Прошлые дни сохраняются со сдвигом +5 ч.
- Минимальный тест. Вход: POST `/attendance/manual`, `occurred_at="2026-10-12T09:00:00"`, офис Asia/Tashkent. Ожидается: в базе `04:00Z`. Ошибку покажет `09:00Z`, а при `now` раньше 08:45Z — 400 `occurred_at`.
