**Как читать приоритеты.** Ниже указаны **итоговые** приоритеты после перекрёстной проверки. Все
проверенные находки подтверждены кодом. Исходные приоритеты часто снижены: многие пути достижимы только
прямым вызовом API или сейчас не проявляются (например, балансов отпуска в рабочей базе нет вовсе).

## Главное (итоговые приоритеты)

### CRITICAL
- **X-SESS-01 (C-01 + C-02 + C-38).** Незакрытую рабочую сессию нельзя закрыть ни HR, ни системой. Сессию
  создаёт только сканер (`attendance/services.py:369`), ручная отметка HR сессии не трогает, статус
  `INVALID` никто не выставляет, а создать заявку на исправление нельзя. Точка по умолчанию — «вход и
  выход», поэтому после одной забытой отметки следующее утро записывается как выход, и учёт
  «переворачивается». *Подтверждено оркестратором.*

### HIGH
- **A-15 — блокер выпуска.** Остатки отпуска (`LeaveBalance`) создаёт только демо-команда
  (`core/management/commands/demo_data.py:277`). В реальной организации ежегодный отпуск со списанием
  подать нельзя. От этой находки зависят все балансовые (X-BAL-01). *Подтверждено оркестратором.*
- **C-04.** Время ручной отметки из CRM сохраняется как UTC, а не во времени офиса. Утренние отметки «за
  сегодня» сервер отклоняет как «в будущем». Проявляется круглосуточно.
- **X-HIST-01 (A-36 + C-10, B-22).** Правка графика, календаря и пояса меняется на месте, без версий.
  Опоздания, нормы и пропуски за всё прошлое пересчитываются, сетка дней в аудит не пишется, закрытый
  месяц не воспроизводится.
- **C-13.** Праздник одного офиса аналитика применяет ко всем офисам региона или организации. Меняется
  число пропусков в CRM.
- **A-10 = B-03.** Аудитории опросов (и условия автоматизаций, фильтры ознакомления) берут всех, кто
  **когда-либо** числился в офисе, отделе или должности. Переведённый получает опросы прежнего
  подразделения.
- **C-18.** Больничный во время отпуска оформить нельзя совсем. Само правило — за HR, но процесс заблокирован.
- **B-01.** В CRM нет действий «Уволить», «Приостановить», «Вернуть», «Отключить Telegram». Бэкенд их
  умеет, единственный путь — Django Admin (только SUPER_ADMIN).
- **B-04.** Аналитика берёт состав на последний день периода и текущий статус. Уволенные и
  приостановленные исчезают из прошлых периодов, переведённый целиком засчитывается новому офису.
  Прошлые отчёты меняются задним числом.
- **A-42.** Нет request id, метрик и сборщика ошибок. `readyz` не видит воркеры и очереди, healthcheck
  бота проверяет только конфигурацию.

### MEDIUM — первопричины, к которым сводится много находок
- **X-DAY-01 (A-07 + A-08 + C-05, C-26).** Нет единого понятия «день». Сервер в UTC, дату берут пятью
  способами. Каждую ночь с 00:00 до 05:00 по Ташкенту скан в день перевода отклоняется
  (`attendance/services.py:120`, `at.date()` в UTC). *Подтверждено оркестратором.*
- **A-09.** «Текущее назначение» реализовано около 25 раз с разной датой и разными условиями по `is_primary`.
- **X-BAL-01 (A-16, A-28, C-19, C-20, C-28).** Ошибки резерва, списания и возврата баланса: пересчёт по
  текущему графику, перенос через год, проверка остатка вне замка. Реальны в коде, но не проявляются, пока
  нет балансов (A-15). Чинить вместе с A-15.
- **X-EXT-01 (A-33 + C-17), C-16, C-23.** Отмена подтверждённой заявки и продления (возврат дней дважды,
  прошедшие дни) — **только через API**: в интерфейсах отмены подтверждённой заявки нет.
- **X-TERM-01 (A-35 + C-21, B-27).** Увольнение не закрывает связанные процессы (будущий перевод, выезды, онбординг, опросы).
- **X-SUSP-01 (A-12 + C-09, B-12).** Смысл приостановки не определён (ВЛ-03 / В9).
- A-25 (гонки привязки Telegram), A-39 (планировщик внутри `GET /telegram/bot/outbox`), C-02, C-03 (разбор
  REVIEW), C-12 (две формулы нормы дня), B-02 (приветствие при приёме снимается outbox), B-05 (ПИНФЛ, дату
  приёма, ошибочную карточку исправить нельзя), B-13 (HR правит свою карточку).
- **Не проявляются сейчас** (поля не задаются из CRM): A-11 и C-07 — ночные смены, C-11 — гибкий график,
  пояс графика, допуск раннего ухода.

## Что правится без решения владельца (предлагаемый первый пакет)

Это технические дефекты, правило в них не спорное. Начну только после вашего «да» (этап 9 мастер-плана,
небольшими блоками: план → тест → исправление → проверка → ревью → регрессия):

1. **X-DAY-01 + C-04.** Единая функция «сегодня» по поясу офиса или организации; ручная отметка — во времени офиса.
2. **C-13.** Праздник офиса — только для своего офиса в аналитике.
3. **A-10 / B-03.** Аудитории опросов, автоматизаций и ознакомления — по назначению, действующему на дату.
4. **B-02.** Приветствие при приёме не снимается молча: доставка после подтверждения или видимость для HR.
5. **A-25.** Блокировки при подтверждении и отключении привязки Telegram.
6. **A-42 (минимум).** Request id в логах, `readyz` с проверкой очереди и воркеров.

## Ограничения

- Находки подтверждены чтением кода и независимой перекрёстной проверкой. На стенде не воспроизводились.
- Аналитика как отдельный этап (формулы, эталонные примеры, сверка CRM, бота и Mini App) — **этап 4**:
  здесь затронута только там, где на неё влияет бизнес-логика (C-12, C-13, B-04).
- Бот и Mini App разобраны в части вызовов API и сценариев сотрудника.
