# Вопросы, требующие решения владельца — с рекомендациями и последствиями

Статус: **на решение.** Код по этим вопросам не меняется до вашего ответа. Рекомендации — мнение
аудитора с обоснованием, а не установленная политика. Ответ по каждой строке: «принять рекомендацию»
или свой вариант. Источники: `stage-2-3-summary.md`, `stage-3a-lifecycle.md` (ВЛ), `stage-3b-attendance-absences.md` (В-),
`q2-offboarding-decisions.md` (увольнение, В1–В10).

## 1. Ключевые решения

| № | Вопрос | Варианты | Рекомендация | Последствия рекомендации | Если ничего не решать |
| --- | --- | --- | --- | --- | --- |
| Р-1 | **Незакрытые сессии** (забыт выход, CRITICAL C-01) | (а) только ручное закрытие HR (нужен инструмент); (б) через N часов после конца смены помечать «требует разбора», без выдуманного выхода; (в) автоматически закрывать по концу смены по графику с пометкой «авто» | **(б) + инструмент HR из (а):** после окончания смены по графику + 4 ч (число — ваше) сессия получает статус «требует разбора»; HR закрывает её с указанием времени или аннулирует; до решения день в табеле помечен, часы не считаются | Учёт перестаёт «переворачиваться» (утро не становится выходом); HR получает очередь разбора; честно: часы не придумываются. Нужны: статус/пометка сессии, действие HR, задача, CRM-экран | Одна забытая отметка ломает учёт следующего дня; HR исправить не может |
| Р-2 | **Ручная отметка HR** (В-2) | создаёт/закрывает сессию; только событие (как сейчас) | **Создаёт и закрывает сессию** (меняет часы и опоздания), время — в поясе офиса, с обязательной причиной и аудитом | Ручная отметка начинает реально исправлять учёт; это и есть инструмент для Р-1 | Ручная отметка ничего не меняет в часах (сейчас) |
| Р-3 | **REVIEW-отметки** (пересланный сменный QR, C-03) | учитывать до решения / не учитывать; кто разбирает и в какой срок | **Учитывать в часах до решения** (проход не блокирован — ваше решение M-9), очередь разбора у HR офиса; HR подтверждает или аннулирует сессию; срок разбора — 5 рабочих дней (ваше число) | Соответствует решению M-9; нужен экран разбора | REVIEW копится без разбора |
| Р-4 | **Начисление отпусков** (A-15 — блокер; В-9) | годовая норма по организации; по стажу/должности; ручной ввод HR; перенос остатка; единица — рабочий день или часы | **Минимум для выпуска:** HR задаёт годовую норму по типу отпуска (по умолчанию для организации, переопределение для сотрудника) + импорт остатков при запуске; единица — **рабочие дни по графику**; отпуск через границу года — **делится по годам**; перенос остатка — по правилу, которое назначит HR (по умолчанию переносится) | Отпуск со списанием можно подавать в реальной организации; исправления баланса (X-BAL-01) делаются вместе | Ежегодный отпуск в реальной организации подать нельзя (блокер) |
| Р-5 | **Версии графиков** (X-HIST-01, В-5) | правка действует на всё прошлое (сейчас); правка = новая версия «с даты» | **Версия «с даты»:** правка графика создаёт новую редакцию с датой начала (по умолчанию сегодня); прошлое считается по прежней редакции; правка задним числом — только с отдельным правом и подтверждением | Прошлые опоздания и нормы перестают меняться; табель воспроизводим. Работа: модель редакций, пересчёт по редакции, миграция текущих графиков в «редакцию 1» | Любая правка графика молча переписывает историю |
| Р-6 | **Закрытие месяца** (ВЛ-13) | нет закрытия; закрытие с запретом правок; закрытие с правкой по отдельному праву | **Закрытие табеля по офису/организации с правкой только по отдельному праву** (`attendance.close_period`), каждая правка закрытого периода — в аудит с причиной | Отчёты за закрытый месяц стабильны; перевод/увольнение задним числом в закрытый месяц требует права | Отчёты прошлых месяцев меняются задним числом (B-04) |
| Р-7 | **Больничный во время отпуска** (C-18, В-4) | запрет (сейчас — процесс заблокирован); больничный прерывает отпуск и возвращает дни; продлевает отпуск | **Больничный прерывает отпуск:** пересекающиеся дни отпуска возвращаются в остаток, больничный оформляется; продление отпуска — отдельной заявкой сотрудника | Процесс разблокирован; баланс честный. Типовая практика СНГ — подтвердить юристом | Больничный во время отпуска оформить невозможно |
| Р-8 | **Отмена идущего отпуска / досрочный выход** (C-16, X-EXT-01) | отмена целиком (сейчас, только API); досрочное завершение с даты | **Досрочное завершение с даты** (возвращаются только непрошедшие дни); полная отмена — только до начала; отмена продления укорачивает отсутствие | Нет возврата прошедших дней и двойного возврата | Сейчас скрыто (только API), но при появлении кнопки баланс исказится |
| Р-9 | **Ночные смены** (X-NIGHT-01, В-6) | поддерживать; запретить | **Запретить сейчас** (форма CRM их и не задаёт): валидация «конец позже начала»; поддержку — отдельным проектом, если появятся ночные офисы | Нет скрытых неверных расчётов; если ночные смены нужны — скажите, это проект | Флаг `crosses_midnight` хранится, но расчёты его не учитывают |
| Р-10 | **Приостановка (SUSPENDED)** (ВЛ-03, В-10, В9) | (а) отстранение: отметки, бот и CRM закрыты, в численности; (б) неоплачиваемый отпуск/декрет: бот для своих данных открыт, отметки закрыты, вне численности; (в) несколько видов с причиной | **(в) с двумя видами на старте:** «отстранение» (как (а)) и «отпуск без содержания/декрет» (как (б)); вид обязателен при приостановке | Поведение отметок, бота, CRM, опросов, напоминаний и аналитики становится определённым | Приостановленный отмечается, получает опросы, сохраняет CRM-доступ |
| Р-11 | **Роль «Руководитель»** (ВЛ-01) | (а) территория офиса (переименовать описание); (б) только подчинённые по `manager_employee_id` на дату; (в) территория + запрет согласовывать своего руководителя и цепочку выше | **(в) сейчас, (б) — следующим шагом**, если оргструктура (руководители) будет заполнена у всех | Конфликт интересов закрыт минимальной правкой; описание роли станет честным | Руководитель согласует заявки всего офиса, в т.ч. своего начальника |
| Р-12 | **Увольнение В1–В10** | см. `q2-offboarding-decisions.md` | В1 (б), В2 (а), В3 (б), В4 (а), В5 «включает администратор», В6–В7 политика HR (рекомендации там), В8 отказ, В9 политика (см. Р-10), В10 до конца дня | Доступ до последнего дня включительно, затем закрыт; история сохранена | Уволенный HR сохраняет доступ к ПДн; бот закрывается раньше срока |

## 2. ВЛ-01…ВЛ-17 (жизненный цикл)

| № | Вопрос | Варианты | Рекомендация | Последствия |
| --- | --- | --- | --- | --- |
| ВЛ-01 | Роль «Руководитель» | см. Р-11 | Р-11 | — |
| ВЛ-02 | Видит ли HR прежнего офиса **новые** события переведённого | (а) да (сейчас, история); (б) только до даты перевода | **(б)** для событий после перевода; историю до перевода — видеть | Совпадает с вашим решением по видимости списков (конкретное право) и M-6 |
| ВЛ-03 | Смысл приостановки | см. Р-10 | Р-10 | — |
| ВЛ-04 | HR правит собственную карточку | (а) ничего; (б) только контакты; (в) всё, кроме статуса и назначения | **(б)** — только контакты; статус, назначение, график, роль, Telegram себе — запрещено | Закрывает самоуправление (B-13); остальное — через другого HR |
| ВЛ-05 | Пребординг: бот и ознакомление до первого дня | да/нет; с какого дня | **Да, ознакомление и бот — за 7 дней до выхода** (число — ваше); отметки — с первого дня | Новичок приходит ознакомленным; приветствие доходит (B-02) |
| ВЛ-06 | Опросы и ознакомление уволенного | (а) закрывать «не требуется»; (б) оставлять, исключать из знаменателя | **(а)** | Нет ежедневных напоминаний-отмен; метрики честные |
| ВЛ-07 | Табельный номер | (а) никогда (только при ошибке, с причиной); (б) свободно с историей | **(а)** | Номер — устойчивый ключ во внешних системах |
| ВЛ-08 | Учётка CRM без карточки, но с кадровыми правами | (а) запретить; (б) разрешить подрядчикам с пометкой | **(а)** для кадровых прав (`employees.*`, `absences.approve`); технические роли без карточки — разрешены | Работает запрет самосогласования (B-14) |
| ВЛ-09 | Двойной контроль привязки Telegram | (а) событие в ленте; (б) подтверждает не тот, кто оформил приём; (в) привязка по ID — только SUPER_ADMIN | **(а) сейчас**, (б) — если будут инциденты | Без лишнего трения; видимость действий |
| ВЛ-10 | Языки уведомлений | ru; ru+uz; по `preferred_language` | **По `preferred_language` (ru/uz)**, по умолчанию ru | Нужны тексты на узбекском (у CRM уже есть RU·UZ) |
| ВЛ-11 | Пауза опросов и ознакомления на время отпуска/больничного | да/нет | **Да** — сроки сдвигаются на длительность отсутствия, напоминания не идут | Меньше раздражения и ложных «просрочек» |
| ВЛ-12 | Пересчёт резерва отпуска при смене графика | да/нет | **Нет** — резерв фиксируется при подаче (минуты по годам), см. Р-4 | Баланс перестаёт «дрейфовать» (C-20) |
| ВЛ-13 | Закрытый период табеля | см. Р-6 | Р-6 | — |
| ВЛ-14 | Подчинённые уволенного руководителя | (а) оставить ссылку; (б) снять автоматически; (в) HR выбирает нового в мастере увольнения | **(в)**, по умолчанию — руководитель уволенного (на уровень выше) | Заявки подчинённых не зависают |
| ВЛ-15 | Закрытие офиса с людьми | (а) запрещать; (б) требовать массовый перевод; (в) разрешать | **(а)** — запрещать, пока есть действующие назначения и активные QR-точки (с подсказкой «перевести»); и закрытый офис не принимает отметки | Нет «призрачных» офисов с людьми и отметками (B-23) |
| ВЛ-16 | Перевод между регионами и график | (а) новый график обязателен; (б) отказ, пока действует график прежнего региона; (в) автоматически график организации | **(а)** — мастер перевода требует выбрать график, если текущий — региональный и чужой новому региону | Сотрудник не остаётся на графике чужого региона |
| ВЛ-17 | Ошибочная карточка | (а) аннулирование с исключением из отчётов; (б) только увольнение с причиной «ошибка» и фильтром | **(а)** — отдельный статус «аннулирована» (только SUPER_ADMIN/HR_ADMIN, с причиной), исключается из всех отчётов и численности, история сохраняется | Отчёты не искажаются ошибочными карточками |
