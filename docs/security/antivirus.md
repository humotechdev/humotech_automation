# Антивирусная проверка загружаемых файлов (ClamAV)

Статус: **механизм реализован и проверяется на изолированном стенде; на рабочем сервере не включён.**
До включения на рабочем сервере риск M-11 (аудит 11.10.2026) считается открытым.
Устанавливать что-либо на рабочий сервер — только по согласованию с серверной командой.

## Как устроено

- Бэкенд проверяет каждый загружаемый файл (справки, больничные, документы и фото сотрудников,
  вложения обращений) **до записи на диск** через `clamd` по протоколу INSTREAM (TCP 3310):
  `apps/backend-api/humotech/files/scanner.py`, вызов — `files/storage.py:store()`.
- Исходы:
  - чистый — сохраняется со статусом `CLEAN`;
  - заражённый — **не сохраняется**, клиент получает 400 `validation_error` с `reason=infected`,
    в журнал приложения пишется предупреждение с сигнатурой (без содержимого файла);
  - сканер недоступен или ответил не вердиктом — загрузка отклоняется **503 `scanner_unavailable`**
    (принцип fail-closed: «принять на потом» нельзя, перевести файл в проверенные позже некому).
- Флаг выключен (`FILES_SCANNER_ENABLED=false`, по умолчанию) — файлы получают честный статус `UNSCANNED`
  и отдаются как раньше (доступ ограничен правами view).
- Выдача: `INFECTED`/`FAILED` не отдаются никому; `PENDING` — только кадровику и только вложением
  (`files/serving.py`).

## Включение (тестовый сервер, `deploy/test-server`)

1. В `.env`: `FILES_SCANNER_ENABLED=true` (при необходимости `FILES_SCANNER_HOST`, `FILES_SCANNER_PORT`).
2. Запуск с профилем: `docker compose --profile antivirus up -d` — поднимется сервис `clamav`
   (образ `clamav/clamav:1.4`, сеть `app`, том `clamav_db`).
3. Дождаться `healthy` у `clamav` (первый старт — загрузка сигнатур, 1–5 минут), затем перезапустить
   backend, чтобы он прочёл флаг.
4. Проверка: загрузить заведомо чистый PDF — `scan_status=CLEAN`; тестовая строка EICAR (не вредоносная,
   стандарт проверки антивирусов) — отказ `infected`; остановить `clamav` — загрузка отвечает 503.

## Требования к ресурсам (рабочий сервер) — для согласования с серверной командой

| Параметр | Значение | Комментарий |
| --- | --- | --- |
| ОЗУ | 1,5–2 ГБ постоянно; пик до ~3 ГБ при перезагрузке базы | clamd держит базу сигнатур в памяти; при обновлении кратковременно две копии (`ConcurrentDatabaseReload`) |
| CPU | 1 vCPU достаточно | проверка PDF/JPEG до 10–25 МБ — доли секунды |
| Диск | ~1 ГБ под базу сигнатур (том) | |
| Сеть | исходящий HTTPS к зеркалам обновлений ClamAV (`database.clamav.net`) | либо внутреннее зеркало (`PrivateMirror` в `freshclam.conf`) при закрытом контуре |
| Порт | 3310/TCP только во внутренней сети `app` | наружу не публиковать |
| Лимит потока | `StreamMaxLength` ≥ максимального размера загрузки (сейчас до 100 МБ по политике, nginx режет 25 МБ) | иначе clamd ответит `size limit exceeded` → 503 |
| Обновления | `freshclam` в том же контейнере, несколько раз в сутки | контролировать возраст базы в мониторинге |

## Эксплуатационные риски и решения, которые нужны серверной команде

- **Недоступность антивируса останавливает загрузки** (fail-closed). Нужны мониторинг healthcheck `clamav`
  и оповещение; при необходимости — второй экземпляр.
- **Устаревшая база сигнатур** — проверка формально проходит, но хуже ловит новые угрозы: мониторить возраст базы.
- **Уже загруженные файлы** (`UNSCANNED`) автоматически не перепроверяются. Ретро-проверка — отдельная
  задача (пройти по `files` со статусом `UNSCANNED`, обновить статус, заражённые — `INFECTED`).
- **Локализация данных:** файлы проверяются внутри контура, наружу уходят только запросы обновления сигнатур.
