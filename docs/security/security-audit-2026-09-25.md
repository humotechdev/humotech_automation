# Аудит безопасности HUMOTECH HR CRM — 25.09.2026

Проверены две вещи: безопасность в целом с исправлениями и все точки ввода. Всё делалось в репозитории и в локальных тестовых базах на вымышленных данных. Внешние адреса, Telegram API, production и инфраструктура компании не затрагивались. Историю git не переписывали.

Действующих секретов в документе нет. Шаги воспроизведения описаны на уровне «какой ввод → что сервер делал».

## 1. Итог для руководителя

**Что уже защищено и подтверждено тестами**
- **Вход HR.** Подбор пароля ограничен общим для всех процессов счётчиком. Сессия живёт 12 часов вместо двух недель. При отключении учётки и смене пароля её сессии обрываются.
- **Изоляция данных.** Сотрудник видит только своё. HR видит только свою организацию и свою область (офис или регион). Построена автоматическая матрица из 250 проверок подмены ID между организациями и регионами.
- **Больничные.** Больничный не может стать подтверждённым и попасть в табель, пока HR не принял справку, не подтвердил получение заявления и не проставил даты. Это верно и при одновременных действиях.
- **Файлы.** Справки, паспорта и вложения чужой области не отдаются. Заражённые и непроверенные файлы сотрудникам не выдаются.
- **Telegram.** Бот больше не превращает текст сотрудников и HR в HTML и не даёт занять чужой кабинет через совпадение @username. Mini App отзывает токены сразу после отвязки или увольнения сотрудника.
- **Сервер и сеть.**
  - Подмена IP через заголовки закрыта.
  - `/admin/` закрыт снаружи, служебный API бота снаружи недоступен.
  - PostgreSQL больше не публикуется на все интерфейсы.
- **Выгрузки.** Формулы в Excel/CSV обезвреживаются. Чужие задания выгрузки не открываются.
- **Тестовый сервер и бэкапы.** Готова отдельная конфигурация тестового сервера с HTTPS. Готова процедура бэкапа базы и файлов, её цикл «бэкап → восстановление → сверка» проверен.

**Что остаётся рискованным**
1. **Critical.** Токен Telegram-бота лежит в истории git на GitHub. Пока его не перевыпустили в BotFather, владелец токена может войти в Mini App от имени любого привязанного сотрудника и управлять ботом.
2. **Во время аудита** значения четырёх секретов стенда попали в журнал этой сессии. В файлы они не попали. Их нужно ротировать вместе с токеном (§6).
3. **Антивируса для загружаемых файлов нет.** При `FILES_SCANNER_ENABLED=false` файлы помечаются как проверенные.
4. **Работающий локальный стенд ещё на старом коде.** Нужно перевыпустить образы и применить миграции. Новые конфиги не проверены вживую на сервере: сборка образов, `caddy validate` и TLS.
5. **Ограничения по устройству системы.** QR-код можно переслать коллеге в течение 30 секунд. Подмену GPS в телефоне сервер не видит.

**Можно ли запускать**
- **Тест с вымышленными данными — можно** после трёх шагов: (1) перевыпустить токен бота и секреты из §6, (2) развернуть новую версию по `deploy/test-server/README.md`, (3) пройти проверки после деплоя из того же README.
- **Работа с реальными данными — пока нет.** Перед этим нужно:
  1. выполнить всё из предыдущего пункта;
  2. решить судьбу истории git (очистка по `docs/security/rotate-telegram-token.md`);
  3. на сервере включить бэкапы по таймеру с хранением вне сервера и провести первое тестовое восстановление;
  4. включить антивирус или принять решение по непроверенным файлам (§5);
  5. получить юридический ответ, где должны храниться персональные данные граждан Узбекистана;
  6. проверить развёрнутый сервер снаружи: TLS, заголовки, закрытые порты.

«Полностью защищённой» систему назвать нельзя. Подтверждено ровно то, что покрыто тестами ниже.

## 3. Атаки, которые не прошли

Все закреплены тестами.

- **SQL-инъекции** в поиске, фильтрах, сортировке, полях конструктора отчётов и tsquery. Raw SQL везде параметризован, сортировка от пользователя не принимается.
- **Хранимый XSS в CRM и Mini App.** `dangerouslySetInnerHTML`, `innerHTML`, `eval` и markdown-рендера нет. `javascript:` в ссылках блокирует React 19.
- **Подмена полей** `organization_id`, `employee_id`, `status`, `approved`, `storage_key`, `occurred_at` в `/me/*` и в CRM игнорируется.
- **initData:** подмена `user.id`, подпись другим ботом, просроченный или будущий `auth_date`.
- **Токен сотрудника** в HR API, `/admin/` и bot-API.
- **QR:** подделка и повтор кода после 30 секунд, код чужого офиса.
- **Файлы:** подмена типа (magic bytes), SVG и HTML, `../`, CR/LF/NUL/RTL в имени, прямой URL к `private-media` и `private-exports`.
- **Больничный** не подтверждается без трёх шагов HR, в том числе с `override_marks`.
- **Формулы XLSX/CSV** со значениями `= + - @ \t \r`.
- **Prompt-инъекции.** Системный промпт — константа. В контекст попадают только опубликованные документы своей организации и области, у модели нет инструментов. SSRF невозможна: сервер ничего не скачивает по пользовательским URL.
- **Демо-изоляция chat id 5000–5999** не обходится.

## 5. Теоретические риски и непроверенное

- **QR-код** можно переслать коллеге в пределах 30 секунд. **GPS** задаёт клиент. Секрет наклейки хранится в базе открытым текстом.
- **initData** можно повторить в пределах 5 минут — это осознанно: перезагрузка вебвью присылает ту же строку.
- **Outbox** работает по принципу «хотя бы один раз». Дубли почти исключены, полностью их уберёт только токен захвата (нужно изменить протокол бота).
- **Антивируса нет.** Предлагается статус UNSCANNED и включение сканера до работы с реальными данными.
- **Персональная ссылка привязки** активирует доступ согласием сотрудника, без HR. **При узнавании по имени** бот показывает ФИО, офис и руководителя. Это не менялось, потому что меняет сценарий; нужно решение продукта.
- **Правила базы знаний для всей организации** теперь меняет только тот, кому видна вся организация. Решение агента, его нужно утвердить.
- **Выгрузка, собранная до сужения прав,** доступна владельцу до истечения 72 часов.
- **Обход экранирования формул** через NBSP или полноширинный `＝` в настоящем Excel не проверялся.
- **Гонки в заявках** проверены имитацией в одном соединении, а не двумя настоящими параллельными.
- **Долгие выгрузки** `sessions` без дат («за всё время») нагрузочно не проверялись: нагрузочные атаки были запрещены.
- **Поле `note`** при закрытии кластера вопросов не ограничено по длине.
- **Маршруты вне матрицы.** В межорганизационную матрицу не вошли маршруты без дешёвых построителей объектов: опросы, база знаний, обращения, `/me/*`, `employees/{id}/onboarding*`. Они покрыты тестами своих зон, но не общей матрицей.
- **Браузерные сценарии CRM** под живым входом не проходились: входит только человек, см. §6.
