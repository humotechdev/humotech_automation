# HUMOTECH HR

HR-система с несколькими регионами и офисами: учёт рабочего времени по QR-кодам,
больничные и отпуска, графики работы, база знаний и ИИ-ассистент для сотрудников.

Face Recognition в системе не используется. Вход и выход фиксируются
сканированием QR-кода офисной точки.

## Приложения

| Приложение | Что делает | Состояние |
|---|---|---|
| [`apps/backend-api`](apps/backend-api) | Единственный сервис с доступом к PostgreSQL. Вся бизнес-логика. | схема БД, модели, миграции, seed, AI-ассистент (выключен), тесты |
| [`apps/employee-telegram-bot`](apps/employee-telegram-bot) | Один бот на сотрудников и HR: роль решает, что человек видит | работает на заглушках, ждёт API |
| `apps/hr-crm` | Веб-интерфейс HR и администраторов | не начат |
| `apps/qr-display` | Экран офиса, показывающий rotating QR | не начат |

## Архитектура

```
                       ┌──────────────────┐
                       │   PostgreSQL     │
                       └────────▲─────────┘
                                │  только backend-api
                       ┌────────┴─────────┐
                       │   backend-api    │  вся бизнес-логика
                       └────────▲─────────┘
                                │  HTTP API
        ┌───────────────┬───────┴───────┬────────────────┐
   ┌────┴────┐   ┌──────┴──────┐  ┌─────┴─────┐   ┌──────┴──────┐
   │ hr-crm  │   │ telegram-bot│  │qr-display │   │  будущие    │
   └─────────┘   └─────────────┘  └───────────┘   └─────────────┘
```

Правила, которые не обсуждаются:

1. К базе подключается **только** `backend-api`. Иначе любая проверка прав обходится.
2. Вся бизнес-логика — в бэкенде: расчёт часов, опоздания, больничные, отпуска,
   права HR, обработка QR-событий, аналитика, аудит.
3. Клиенты только отправляют команды и рисуют ответы. Ничего не считают сами.
4. `packages/` — только действительно общий код. Бизнес-логика приложений туда не переезжает.
