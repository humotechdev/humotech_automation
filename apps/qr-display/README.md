# qr-display

Экран показа динамического QR в офисе HUMOTECH. React + TypeScript + Vite.

Висит на стене и работает без человека: включили питание — через секунду
показывает код. Никаких настроек на месте, кроме одноразового сопряжения.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5175
npm test         # vitest, без браузера
npm run build    # tsc --noEmit + vite build
```

## Как экран получает доступ

Два шага, и оба нужны.

1. **HR заводит устройство** и один раз показывает код сопряжения:

   ```bash
   cd apps/backend-api
   python manage.py qr_display_device --create \
       --organization-code HUMO --office-code MAIN \
       --qr-point-code MAIN_ENTRANCE --name "Планшет у входа"
   ```

   Код печатается один раз. В базе от него остаётся только хеш —
   восстановить его нельзя даже суперпользователю. Это неудобно намеренно:
   восстановимый код означал бы, что дампа базы достаточно, чтобы
   подключить свой экран. При утере — `--reissue`.

2. **Экран вводит код** и получает свой постоянный `credential`. Код
   сопряжения при этом гасится: подсмотренный код бесполезен, если экран
   уже сопряжён.

Отзыв — `--revoke`. Действует со следующего запроса: старый код с экрана
убирается сразу, а не доживает свои полминуты.

## Чего экран не выбирает

Ничего. Ни офиса, ни точки, ни направления. Он предъявляет `credential`
и получает то, что положено именно ему; офис и точка приходят в ответе,
а не уходят в запросе. Подставить `office_id` в адрес бесполезно —
читать его некому.

## Где лежит credential и почему в localStorage

Здесь `localStorage`, и это НЕ противоречит правилу Mini App «никогда
не localStorage».

В Mini App хранится доступ **человека** на устройстве, которое могут взять
другие: следующий открывший увидел бы чужую сессию. Здесь хранится доступ
**самого устройства** — планшета, привинченного к стене, — и он обязан
пережить перезагрузку и утренний запуск без человека рядом. Повторить
правило Mini App значило бы требовать, чтобы кто-то приходил сопрягать
экран после каждого отключения питания.

Угрозы разные — ответы разные. Это решение, а не недосмотр.

## Обновление кода

Следующий код запрашивается ЗАРАНЕЕ, за треть срока до истечения. Если
ждать до конца, между истечением старого и появлением нового будет окно,
в котором на экране висит заведомо нерабочий код: человек в это окно
сканирует и получает отказ.

При обрыве связи прежний код остаётся, пока действует, — обрыв на десять
секунд не повод гасить работающий экран. Пауза между попытками растёт
до минуты: экран с упавшей сетью иначе бьётся в сервер сутки напролёт.
Связь восстановится, и экран оживёт сам.

## Что на экране

Название офиса, название точки и сам код. Больше ничего. Мимо экрана
ходят посетители, и персональных данных на нём нет и быть не может.

Тёмная тема не поддерживается намеренно: QR читается по контрасту тёмного
на светлом, и «умный» экран, перекрасивший его ночью, просто перестанет
сканироваться.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `VITE_API_URL` | адрес API, по умолчанию `/api/v1` |
| `VITE_BACKEND_ORIGIN` | куда проксировать `/api` в разработке |

Секретов здесь нет и быть не может: всё, что попадает в `VITE_*`,
оказывается в собранном бандле. Ключ подписи QR живёт только на сервере
и во frontend не уходит ни при каких условиях.
