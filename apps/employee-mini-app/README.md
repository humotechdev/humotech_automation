# employee-mini-app

Telegram Mini App сотрудника HUMOTECH: отметка по QR, статистика, история,
больничные и отпуска.

Подробности: [docs/architecture/employee-side.md](../../docs/architecture/employee-side.md),
схема привязки — [telegram-linking.md](../../docs/architecture/telegram-linking.md).

## Запуск

```bash
npm install
npm run dev      # http://localhost:5174
npm test         # vitest, без браузера
npm run build    # tsc --noEmit + vite build
```

Запросы к `/api` в режиме разработки проксируются на backend
(`VITE_BACKEND_ORIGIN`, по умолчанию `http://127.0.0.1:8000`), поэтому origin
один и CORS в разработке не участвует вовсе.

## Что здесь есть

```
src/auth.ts       initData -> внутренний токен, пять состояний входа
src/api.ts        обращения к /me/*, один разбор ошибки на всё приложение
src/scanner.ts    три пути сканирования и тексты результатов
src/format.ts     секунды в часы, коды в слова, время в пояс офиса
src/screens/      главный экран, отметка, статистика, история, отсутствия
src/App.tsx       вход и плоская навигация
```

`auth.ts`, `api.ts`, `scanner.ts` и `format.ts` не знают ни про React,
ни про DOM: им нужны только `fetch` и данные. Поэтому их тесты идут без
браузера и без jsdom, а экраны остаются тонкими.

## Сканирование

Три пути, от лучшего к запасному:

1. **`Telegram.WebApp.showScanQrPopup`** — собственный сканер Telegram.
   Разрешение на камеру у приложения уже есть, спрашивать нечего,
   работает в мобильном вебвью на обеих платформах, библиотека не нужна;
2. **`BarcodeDetector`** — встроенный в браузер декодер;
3. **ручной ввод** — если камеры нет или в доступе отказано. Не «красивое
   падение», а рабочий путь: под кодом на экране напечатан он же текстом.

jsQR и подобное не подключается: библиотека весит больше всего остального
приложения вместе взятого, а нужна ровно на том устройстве, где уже есть
первый или второй путь.

Камера включается **только по нажатию**. Ни одного обращения к ней при
открытии экрана: приложение, спрашивающее камеру само по себе, выглядит
подозрительно — и справедливо.

Окно сканера не закрывается на чужом QR. Иначе одна случайная наклейка
в кадре прерывала бы отметку.

## Что не сохраняется

**QR-код.** Ни в состоянии после отправки, ни в хранилище: он рабочий
секрет полминуты, и лишняя копия ни к чему.

**Отметки «в офлайне».** Их нет и не будет. Решение принимает сервер,
а накопить отметки, чтобы отправить позже, значило бы позволить
отметиться задним числом.

## Пять состояний

| Состояние | Когда | Что видит человек |
|---|---|---|
| `authenticated` | привязка подтверждена | личный кабинет |
| `pending` | перешёл по ссылке, HR не подтвердил | «ожидает подтверждения» |
| `unlinked` | Telegram ни к кому не привязан | «попросите ссылку у HR» |
| `outside-telegram` | открыто вне Telegram | «откройте из чата с ботом» |
| `error` | сеть, сервер, отвергнутая подпись | текст и кнопка «ещё раз» |

`outside-telegram` — отдельное состояние, а не ошибка: подписанной строки
просто нет, и запрос в этом случае **не отправляется вовсе**.

Отвергнутая подпись тоже не выдаётся за отсутствие привязки: в одном случае
надо открыть приложение заново, в другом — идти к HR.

## Безопасность

**`initDataUnsafe` не читается.** Это те же поля, но без подписи: любой, кто
открыл страницу в обычном браузере, подставит туда что угодно. Наружу уходит
только исходная подписанная строка, а кто это и есть ли доступ — отвечает
backend.

**Токен бота во frontend не попадает никогда.** Подпись проверяет сервер,
у которого этот токен есть.

**Наружу уходит только `init_data`.** Ни `telegram_user_id`, ни `employee_id`,
ни `organization_id` не передаются — подделать можно только то, что где-то
принимается.

**В отметке — только код и ключ попытки.** Ни офиса, ни направления,
ни времени: всё это решает сервер. Прислать «я выхожу» нечем.

**Токен уходит заголовком, а не в адресе.** Адрес попадает в журналы
сервера, в историю и в `Referer` целиком.

### Где хранится токен и почему

В памяти, копия — в `sessionStorage`.

* `localStorage` **не используется**: он переживает закрытие Mini App и
  остаётся в вебвью неограниченно долго. На общем устройстве следующий
  человек открыл бы чужую сессию;
* одной памяти мало: перезагрузка страницы внутри вебвью не обновляет
  `initData` — строка сохраняет прежний `auth_date`, а он живёт пять минут.
  Без `sessionStorage` перезагрузка через пять минут после запуска означала
  бы «откройте приложение заново»;
* `sessionStorage` очищается вместе с вкладкой вебвью, то есть при закрытии
  Mini App — ровно та граница, которая здесь нужна.

Доступ к хранилищу обёрнут в `try`: в приватном режиме он бросает исключение,
и приложение из-за этого падать не должно.

Выход (`Выйти`) стирает только эту сессию. Отключить привязку целиком может
лишь отдел кадров — иначе доступ отзывался бы с того самого устройства,
которое мог взять кто угодно.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `VITE_API_URL` | адрес API, по умолчанию `/api/v1` |
| `VITE_BACKEND_ORIGIN` | куда проксировать `/api` в разработке |

Секретов здесь нет и быть не может: всё, что попадает в `VITE_*`, оказывается
в собранном бандле.
