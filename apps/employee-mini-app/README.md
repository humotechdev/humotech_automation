# employee-mini-app

Telegram Mini App сотрудника HUMOTECH. Сейчас здесь только **авторизация** —
личный кабинет будет следующим этапом.

Подробности схемы привязки: [docs/architecture/telegram-linking.md](../../docs/architecture/telegram-linking.md).

## Запуск

```bash
npm install
npm run dev      # http://localhost:5174
npm test         # vitest, без браузера
npm run build    # tsc --noEmit + vite build
```

Запросы к `/api` в режиме разработки проксируются на backend
(`VITE_BACKEND_ORIGIN`, по умолчанию `http://127.0.0.1:8000`), поэтому origin
один и CORS в разработке не участвует вовсе.

## Что здесь есть

```
src/auth.ts     логика: initData -> запрос -> одно из пяти состояний
src/App.tsx     пять экранов, по одному на состояние
src/main.tsx    монтирование
```

`auth.ts` не знает ни про React, ни про DOM: всё, что ему нужно, — `initData`
и `fetch`. Поэтому его тесты идут без браузера и без jsdom, а экраны остаются
тонкими.

## Пять состояний

| Состояние | Когда | Что видит человек |
|---|---|---|
| `authenticated` | привязка подтверждена | имя и табельный номер |
| `pending` | перешёл по ссылке, HR не подтвердил | «ожидает подтверждения» |
| `unlinked` | Telegram ни к кому не привязан | «попросите ссылку у HR» |
| `outside-telegram` | открыто вне Telegram | «откройте из чата с ботом» |
| `error` | сеть, сервер, отвергнутая подпись | текст и кнопка «ещё раз» |

`outside-telegram` — отдельное состояние, а не ошибка: подписанной строки
просто нет, и запрос в этом случае **не отправляется вовсе**.

Отвергнутая подпись тоже не выдаётся за отсутствие привязки: в одном случае
надо открыть приложение заново, в другом — идти к HR.

## Безопасность

**`initDataUnsafe` не читается.** Это те же поля, но без подписи: любой, кто
открыл страницу в обычном браузере, подставит туда что угодно. Наружу уходит
только исходная подписанная строка, а кто это и есть ли доступ — отвечает
backend.

**Токен бота во frontend не попадает никогда.** Подпись проверяет сервер,
у которого этот токен есть.

**Наружу уходит только `init_data`.** Ни `telegram_user_id`, ни `employee_id`,
ни `organization_id` не передаются — подделать можно только то, что где-то
принимается.

### Где хранится токен и почему

В памяти, копия — в `sessionStorage`.

* `localStorage` **не используется**: он переживает закрытие Mini App и
  остаётся в вебвью неограниченно долго. На общем устройстве следующий
  человек открыл бы чужую сессию;
* одной памяти мало: перезагрузка страницы внутри вебвью не обновляет
  `initData` — строка сохраняет прежний `auth_date`, а он живёт пять минут.
  Без `sessionStorage` перезагрузка через пять минут после запуска означала
  бы «откройте приложение заново»;
* `sessionStorage` очищается вместе с вкладкой вебвью, то есть при закрытии
  Mini App — ровно та граница, которая здесь нужна.

Доступ к хранилищу обёрнут в `try`: в приватном режиме он бросает исключение,
и приложение из-за этого падать не должно.

Выход (`Выйти`) стирает только эту сессию. Отключить привязку целиком может
лишь отдел кадров — иначе доступ отзывался бы с того самого устройства,
которое мог взять кто угодно.

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `VITE_API_URL` | адрес API, по умолчанию `/api/v1` |
| `VITE_BACKEND_ORIGIN` | куда проксировать `/api` в разработке |

Секретов здесь нет и быть не может: всё, что попадает в `VITE_*`, оказывается
в собранном бандле.
