# employee-telegram-bot

Telegram-бот HUMOTECH — **один бот на сотрудников и HR**: [@humotech_hr_bot](https://t.me/humotech_hr_bot)

Что видит человек, определяется полем `role` из `GET /employees/me`. Меню команд
задаётся персонально для каждого чата (`setMyCommands` + `BotCommandScopeChat`),
поэтому сотрудник не видит HR-команд. **Права проверяет backend-api, не бот.**

## Привязка аккаунта

Привязку начинает **отдел кадров**: HR выдаёт сотруднику персональную
одноразовую ссылку `https://t.me/<бот>?start=link_<ТОКЕН>`. Бот участвует
одним вызовом — сообщает backend токен и подтверждённый Telegram-аккаунт.

Переход по ссылке **доступа не даёт**: привязка создаётся в состоянии
ожидания и становится рабочей только после подтверждения HR. Ссылку можно
переслать или потерять, и по ней привязывается тот, кто её открыл, — HR
обязан увидеть, кто это был.

Своими силами (по телефону и коду) привязаться нельзя: такого пути больше
нет. Порядок целиком — [docs/architecture/telegram-linking.md](../../docs/architecture/telegram-linking.md).

Бизнес-логики привязки в боте нет: handler разбирает нагрузку `/start`,
вызывает клиента и подбирает текст под КОД ответа. Срок, одноразовость,
отзыв и чей это сотрудник решает backend.

## Запуск

```bash
cd apps/employee-telegram-bot
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # Linux: .venv/bin/python
cp .env.example .env        # вписать BOT_TOKEN
PYTHONPATH=. .venv/Scripts/python.exe -m src.main
```

Бот работает на long polling. Webhook понадобится, когда появится публичный адрес.

## Режимы

`API_MODE` в `.env`:

| Значение | Поведение |
|---|---|
| `stub` | фейковые данные, `backend-api` не нужен — так бот работает сейчас |
| `live` | реальные HTTP-запросы на `BACKEND_API_URL` |

В режиме `stub` ссылка привязки принимается любая, а каждый отказ можно
посмотреть отдельным токеном — так все ветки ответа проходятся руками,
не поднимая backend:

| Полезная нагрузка `/start` | Что покажет бот |
|---|---|
| `link_что-угодно` | «ждёт подтверждения HR» |
| `link_stub-expired` | срок истёк |
| `link_stub-revoked` | ссылка отозвана |
| `link_stub-used` | уже использована |
| `link_stub-pending` | по ней уже перешли |
| `link_stub-invalid` | недействительна |
| `link_stub-telegram_taken` | Telegram занят другим сотрудником |

Настоящий токен — 43 случайных символа, ни одно из этих слов в него попасть
не может.

Разделы для привязанного сотрудника (профиль, отпуск, HR-панель) в режиме
`stub` работают на заранее заведённых демо-токенах: обмена подтверждённой
привязки на токен доступа для бота пока нет — это следующий этап.

Переключение на настоящий бэкенд — это `API_MODE=live` и ничего больше:
`StubBackendClient` и `LiveBackendClient` реализуют один интерфейс и возвращают
payload'ы одной формы.

## Что готово

| Раздел | Состояние |
|---|---|
| Привязка по одноразовой ссылке от HR | работает |
| Уведомление «HR подтвердил привязку» | не начато: канала backend → bot нет |
| Токен доступа для самого бота | не начат — разделы ниже работают на заглушке |
| Главное меню с учётом роли | работает |
| Персональное меню команд по ролям | работает |
| Профиль | работает |
| Заявка на отпуск (FSM, 4 шага) | работает — **эталон для остальных сценариев** |
| HR: очередь заявок, одобрить / отклонить с причиной | работает |
| HR: сводка «кто на месте», поиск сотрудника | работает |
| Мои отметки, статистика, больничный, корректировки, вопросы | заглушки — ждут бэкенд |
| Обратный канал `POST /internal/notify` | не начат |
| Ни один апдейт не остаётся без ответа (fallback-роутер) | работает |

## Структура

```
src/
├── main.py             точка входа: Bot, Dispatcher, middleware, роутеры, обработчик ошибок
├── config/settings.py  всё из .env, ничего не хардкодится
├── api/                ЕДИНСТВЕННЫЙ выход наружу
│   ├── client.py       BackendClient (интерфейс) + LiveBackendClient
│   ├── stub.py         StubBackendClient — данные по контракту, пока нет бэкенда
│   ├── errors.py       401/403/409/... в терминах контракта
│   └── tokens.py       telegram_id -> access_token (в памяти; для прода → Redis)
├── middlewares/auth.py резолвит токен и роль до фильтров роутеров
├── utils/
│   ├── filters.py      RoleFilter — вешается на роутер целиком
│   └── commands.py     персональное меню команд для чата
├── handlers/
│   ├── start/          /start, привязка, /menu, отмена
│   ├── vacation/       полный FSM — образец для больничного и корректировок
│   ├── hr/             HR-раздел за RoleFilter("hr", "admin")
│   ├── fallback.py     ПОСЛЕДНИЙ роутер: отвечает на всё неразобранное
│   └── ...             остальные разделы — заглушки
├── keyboards/menu.py   клавиатуры, подписи кнопок
├── messages/ru.py      тексты (позже → locales/ для мультиязычности)
└── states/flows.py     FSM-сценарии
```

## Правила, которые нельзя нарушать

1. **Никаких драйверов БД в зависимостях.** Бот не ходит в PostgreSQL — только в
   `backend-api` через `src/api/`.
2. **Бот ничего не считает.** Часы, опоздания, остаток отпуска, права — всё это
   возвращает бэкенд. Бот форматирует и рисует.
3. **Роль приходит с сервера** и влияет только на отрисовку. Если хендлер всё же
   вызовет HR-эндпоинт, бэкенд обязан ответить `403`.
4. **`.env` не коммитится.** Токен бота — пароль от бота. Скомпрометирован →
   `/revoke` в @BotFather.

## Тесты

```bash
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m pytest                              # 26 тестов
PYTHONPATH=. .venv/Scripts/python.exe tests/smoke_contract.py   # 32 проверки
PYTHONPATH=. .venv/Scripts/python.exe tests/smoke_routing.py    # 28 проверок
```

Проверка настроек без единого обращения наружу:

```bash
PYTHONPATH=. .venv/Scripts/python.exe -m src.check_config
```

Сети не требуют: `smoke_contract` гоняет `StubBackendClient` против форм из
контракта, `smoke_routing` прогоняет апдейты через настоящий `Dispatcher`
с подменённой сессией Telegram. Запускать перед каждым коммитом.

## Контракт

`packages/api-contracts/telegram-bot.v1.md` — единственный источник правды по
эндпоинтам. Меняется контракт → меняются обе стороны, не наоборот.
